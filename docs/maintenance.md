# 维护约定

## 先定位职责

从 [architecture.md](../architecture.md) 找模块，不必通读所有源码。默认文案在 `src/state/prompts/`，类型在 `src/state/settings/`；`settings.ts` 保留旧导出路径、运行态与迁移逻辑。

本轮只移动默认文案，不改变字符串、配置键或历史兼容路径。下线的 NAI 默认协议仍为旧调用保留。图库体积扫描为明确暂停功能，未在整理中恢复或整条删除。

## 文件大小

运行 `npm run hooks:install`，为当前 Git 仓库启用 `.githooks/pre-commit`。已有其他 hooksPath 时停止，不覆盖现有钩子。

钩子读取暂存区内容，规则如下：

- 新文件上限 20,000 字节，约 5,000 token。
- 既有超标文件列在 `scripts/file-size-baseline.json`。允许保持或缩小；每次与 HEAD 比较后不允许重新增大。
- `dist/`、锁文件和机械生成的 `src/manga/table.ts` 不检查。普通源码和测试没有通用豁免。
- 被拒绝时按职责拆文件，不抬高基线或关闭检查。清单不表示这些文件已完成拆分。
- 在安装副本做 Git 操作前，确认是自己的开发仓库；安装脚本不推送、不暂存文件。

## 文档分工

- README：使用入口和更新概述。
- architecture：源码定位和跨模块陷阱。
- DESIGN：现行产品边界。
- docs：具体协议，不在多个文档复制完整判据。
- PUBLIC_API：第三方调用契约，公开结构变更须同步更新。

## 安装与回退

先备份、在工作副本修改、跑类型检查和测试，再构建。安装前比较原文件哈希，发现并发修改就停止覆盖。同步构建产物后核对服务实际返回的文件。

不在整理中修改个人渠道、API Key、世界书、角色状态、版式库、私有提示词规范或 DSH 数据。代码发布与运行验证分别记录。

## 工具

本项目按需要使用编码和浏览器工具；视频生成、宠物和 Office 工具不必为本项目常开。全局开关由用户管理。
长对话可压缩上下文；换项目时新开对话。只有明确委派并行工作时才使用子代理，并只汇总相关证据。
