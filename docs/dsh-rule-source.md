# DSH 规范来源

设置 → 副 API → 开启 DSH 持久 Agent 会话 → 规范来源。

- 插件规范（默认）：保持现有固定分组与同步行为。
- DSH Skill：仅对 ComfyUI 漫画 Layout（manga）规划生效；从 DSH 请求中移除 `spec`、`check` 分组。前置提示词 `prefix`、宿主输出协议 `contract` 继续发送。
- 当前角色库与锁定信息、正文、角色卡、世界书和冷却白名单等动态资料继续随每轮请求发送；专属图片模式首次发送完整图册，后续复用已确认的会话图册，变化或失效时补发，详见 [版式示意图接口](layout-vision.md)。
- 规范原文继续保存在插件设置中，选择 Skill 不会清空或改写它们。普通 API 和其他后端/协议不受该选项影响。

## 绑定与校验

Skill 名称仍只在 DSH 的插件接入项维护，柏宝绘不新增一份绑定配置。
插件先通过当前服务的 `/v1/bridge/capabilities` 查询所选专属入口对应的 `skillId`；未绑定或入口禁用则停止发送。
随后将 `dsh_session.skill_id` 作为绑定断言传给桥接，并核对响应中的 `skill_id` 后才确认本地会话状态。
图片模式沿用同一次能力查询结果，不额外重复查询。

绑定回显仅确认 Skill 正文由桥接加载，不保证 `references/` 已被读取。
使用分册 Skill 时，须先在 DSH 侧实现分册展开或受控的资源读取能力；当前插件不读取本地 Skill 文件，也不执行其脚本。
Skill 内容或绑定更新后如桥接要求重建会话，使用“重建 DSH 会话”。

## 会话隔离

两种来源使用独立绑定，保留旧会话。切回插件来源可沿用之前的插件绑定，不混用 Skill 会话。
普通持久模式的 Skill 请求使用独立任务 `manga-skill`；专属模式将来源纳入专属 chat ID 的计算。
模糊网络重试继续复用同一来源的请求；切换来源不会重放另一来源待重试的请求。
“重新发送宿主协议”只同步保留的前置提示词与宿主协议，不会把插件主规范和检查指导发回 Skill 会话。
