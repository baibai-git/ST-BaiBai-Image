# 版式示意图接口

设置 → 漫画 Layout → 版式说明方式：文字空间说明 / 示意图＋精简槽位清单。
默认文字模式，图片模式需要支持视觉输入的副 API。跟随主 API 暂不支持图片，会明确提示切换渠道。

拼图从所有启用且符合本轮画布、方向设置的版式实际几何现算，不按冷却筛掉版式。每张最多 4 套，2×2 排列，PNG 1440×1800。
横竖方向分别分组，保留原比例、四边形、panel 数组编号、槽位键和层级。
新增、删除、停用、改 ID、改框或画布后，下次请求自动更新图册与空间目录；冷却只改变本轮文字白名单，不改变图册版本。
设置页预览全部启用版式，实际请求另按方向及画布筛选。余数不足 4 套时留空。

## 发送给兼容端点的消息

图片放在动态 `user` 消息中，示例中的 `<PNG_BASE64>` 仅为占位符：

```json
{
  "role": "user",
  "content": [
    {"type":"text","text":"【会话完整版式图册】（第 1/1 组）\n本消息第 1 张（总图 1）：portrait，layout ID 1、2、3、4\n图中 P 编号为输出 panel 编号；只参考几何，不把图例或标签画进作品。"},
    {"type":"image_url","image_url":{"url":"data:image/png;base64,<PNG_BASE64>","detail":"high"}}
  ]
}
```

DSH 按能力接口的 `image_input.max_images_per_message` 重新分组，同时标明消息内序号和全局总图序号。每张拼图仍最多 4 套；若生成 6 张拼图，上限 20 时放进同一条 user 消息，上限 4 时分成 4＋2 两条，不增加模型调用轮数。其他 API 按每条 4 张分组。图片数为各方向版式数分别除以 4 后向上取整之和。
本轮动态文字只提供可选 ID、冷却与回退规则；完整图册及精简槽位/用途目录提供几何信息，不授予选择权限。图片模式移除重复百分比位置说明。
固定规范仍为纯文本。`dsh_session` 协议、专属入口、Skill 绑定及 `fixed_message_count` 语义不变；图片不进入固定规范同步。

## DSH 专属会话保留（ST-bridge 0.15.0 起）

专属模式要求桥接声明 `layout_atlas: {"supported":true,"mode":"session-prefix-v1"}`。

- 首次生成发送完整图册和空间目录；`dsh_session.layout_atlas.hash` 标识图册版本，`message_indices` 指向本请求中的图册 user 消息。
- 桥接独立保存原生图册节点，清理旧正文和回答时保留该节点；后续相同会话和图册只传同一 hash 及空索引，不重复上传图片或目录。固定选版说明和回退控制格式也随图册保留，后续只更新可选/禁用 ID、冷却窗口、放宽状态及是否允许回退。本轮正文与角色资料照常发送。
- 插件核对响应 `dsh_session.layout_atlas_hash` 后保存确认状态；图册变化或重建会话后重新发送完整图册。
- 图册丢失时桥接返回 `410 layout_atlas_required`；插件清除绑定，在剩余重试次数内重新同步并发送完整图册。模糊网络重试保留原请求与请求 ID。
- 普通持久模式也只在会话首次生成或图册版本变化时携带完整图册、空间目录与固定说明；插件按酒馆聊天和渠道在聊天元数据中保存已发送版本，后续只发白名单。不发送专属模式的 `layout_atlas` 协议字段，沿用普通会话历史中的原始图册。同步规则不清除此状态；重建、410 失效或远端会话 ID 变化后重新发送。其他非 DSH API 每轮携带完整图册。
- 普通模式依赖远端保留历史，插件不能探测其静默删除或压缩图片的行为；需要重新载入图册时可重建 DSH 会话。减少重复上传不保证模型输入 Token 或账单减少。

## DSH 图片能力检查

插件在实际发送带图的 DSH generate 请求前，读取所选渠道同一服务 origin 下的 `/v1/bridge/capabilities`，检查 `image_input` 的模式、角色、MIME 和数量/大小限制。纯文字及固定规范控制请求不做图片预检。旧桥接、无法连接或认证失败会明确报错，不静默去图。
同一 origin 的已启用 Tavern 适配器若保存了配对设备 token，则预检沿用它；否则使用当前渠道密钥，设备 token 不发往其他 origin。

- 接收并校验上述 `user.content[]` 中的 `text` 和 `image_url`，将图片作为真正的视觉输入传给 Agent；不要展平、丢弃或把 base64 变成正文。
- 保持消息顺序、图组编号及本轮图片对应关系；请求幂等哈希须覆盖图片内容，图片变化不能复用旧请求结果。
- 图册只在当前插件、任务和会话内复用；本轮选择权限始终以动态文字白名单为准。
- 确认目标模型支持视觉。对不支持的模型或图片格式明确报错，避免静默退化为缺少几何的精简文本。
- 按实际 PNG/base64 请求大小核对桥接和上游请求体上限；本机 21 套、6 张图实测仅图片 data URL 合计约 2.03 MiB，还需加上规范和正文；日志只记图片数、字节数或哈希，不记录图片正文。
- 插件历史只保存图片数量，不保存 base64；图片 Token 以 API 返回的 usage 为准，无 usage 时不靠文本分词器估算图片。

未部署图片输入能力时使用文字模式；专属图片模式另需上述图册保留能力。
