# 柏宝绘专用世界书

在「设置 → 专用世界书设置 → 书单模式」选择：

- **跟随酒馆正常世界书**：沿用酒馆当前的全局、角色、聊天及人设世界书。
- **仅柏宝绘专用书**：只扫描下方所选书单；为空时不携带世界书。
- **酒馆正常世界书＋柏宝绘专用书**（0.3.14）：保留酒馆当前书单，合并下方专用书后进行一次原生扫描，支持两边条目互相递归触发；同一书中的同一条目不会因重复选书而增加一份。专用书为空时跟随酒馆。

升级保留原模式：旧版关闭仍跟随酒馆，旧版开启仍仅扫描专用书，不自动切换叠加。

书单保存在柏宝绘自己的设置中，不修改酒馆全局、角色、聊天或用户人设的世界书绑定。专用书不需要挂到酒馆全局；若只想让柏宝绘读取，也不要另行绑定到酒馆对话。

条目的常驻（蓝灯）、关键词（绿灯）、禁用、概率及递归等激活逻辑由酒馆原扫描器执行，选书不会把全部条目强制激活。现有整本排除与条目名过滤仍生效。内容沿用原有宏及可选 EJS 渲染流程。

## DSH 世界书动态保护（0.3.13）

启用 DSH 持久会话时，柏宝绘在每轮世界书完成激活、排除和渲染后，为最终动态 system 消息添加成对的 `<<<STB-KEEP>>>` / `<<<STB-/KEEP>>>`。这保护的是当前实际发送的条目，不会强制激活整本书，也不改变专用书单或显式排除设置。普通 API 沿用原消息。

配合 **ST-bridge 0.15.1 或更新版本**，整条相同消息和其中重复段落都不会被快照前后缀裁剪丢弃；旧桥接仅有段落级保护，整条消息仍可能先被移除。保护符号在进入模型前剥离。世界书继续按每轮动态材料发送，不加入首次固定规范组。

更新柏宝绘后刷新酒馆；更新桥接后重启 DSH。测试覆盖连续两轮正文变化而世界书不变、条目变化、排除和普通 API 行为。

## 一次性安装宿主兼容补丁

当前酒馆扫描接口没有独立及叠加书单参数，因此这两种模式需要一个小型宿主兼容补丁。补丁给扫描器增加本次请求专用的书单参数，普通酒馆请求不传该参数，保持原流程；不临时修改全局书单，也不替换条目的触发算法。

在插件目录执行（需要本机 Node.js）：

```sh
node scripts/patch-worldbook-scanner.mjs --check
node scripts/patch-worldbook-scanner.mjs --apply
```

脚本会向上寻找酒馆根目录，也可显式指定：

```sh
node scripts/patch-worldbook-scanner.mjs --apply "PATH_TO_SILLYTAVERN"
```

`--check` 只检查兼容性；`--apply` 修改酒馆 `public/scripts/world-info.js`，先在同目录生成带时间戳的备份。结构不匹配时停止，不尝试猜改。重复安装不会重复写入。0.3.14 需要再次执行脚本，将旧版仅支持专用书的补丁升级为支持叠加书单。安装后刷新酒馆。

酒馆更新可能覆盖这个补丁，需要重新执行检查与安装。恢复时使用安装输出的备份文件；仅在宿主未被后续更新或修改时直接还原，避免覆盖新版本。未安装补丁时，专用模式明确报告接口不可用，不偷偷使用酒馆书单或忽略所选书；关闭专用模式仍可使用原流程。

检查：本仓库测试覆盖书单隔离、配置迁移与保存、空书单、排除过滤和接口缺失。它们不等于模型生成效果验收。
